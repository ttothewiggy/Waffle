# Daybook v0.1

Mobile-first personal journal. Open directly into today, write freely, attach photos, see save confirmation, close and return, browse earlier days. One editable entry per local calendar day. No account or invented sample memories.

## Visual direction
An ink-blue notebook: crisp ivory paper, editorial serif headings, blue ruled detail, restrained orange bookmark, generous touch targets. Desktop gains a quiet side rail; phone retains the same writing-first flow.

## Model
Entry: date (YYYY-MM-DD primary key, local time), text, photos, createdAt, updatedAt, schemaVersion. Photo: UUID, name, MIME type, Blob. IndexedDB commits text and photo data together. Successful save means the transaction completed. Storage failures retain editor content and expose retry.

## Structure
- app/: Next.js route, metadata, global styles
- components/: journal experience
- lib/storage/: repository contract and IndexedDB adapter
- lib/integrations/: future encryption, AI, PDF, and native contracts
- public/: PWA manifest, icons, offline worker
- tests/: persistence and date behavior

## Delivery sequence
1. Scaffold Next.js/React/TypeScript and Git.
2. Build Today, attach/remove images, save immediately on changes.
3. Add calendar/history with editing of previous days.
4. Add install metadata and offline shell; verify production build and persistence.

## Boundaries
Device-local, unencrypted browser storage. Clearing site data removes entries. No sync or recovery backup in v0.1. Request persistent browser storage where supported but never promise permanence. Avoid analytics and transmitting journal content. Future production encryption requires key recovery and threat-model design before connecting cloud storage. Capacitor can consume the static out/ build; device integrations sit behind interfaces. Next.js server features are intentionally unused so Android does not require a UI rewrite.
