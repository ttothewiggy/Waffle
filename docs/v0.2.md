# Waffle v0.2 — backup and dictation

## What changed

- Backup & restore is under About your journal / Your journal. A versioned JSON file includes text and binary photos encoded as base64. Files stay in the browser; imports are not uploaded. Limit: 100 MB per backup.
- Restore validates structure, dates, duplicate days and photo IDs, formats, sizes, and decodability before showing a preview. Keep existing days is the default. Explicit replacement overwrites only dates in the backup. All import writes share one IndexedDB transaction; failure rolls back the entire import.
- Dictate opens a modal pinned to the selected date. MediaRecorder records at a requested 64 kbps, up to 3 minutes / 3 MB. Stop, listen, explicitly send for transcription, edit, then append to the entry. Closing discards with confirmation; hiding the page stops recording. Microphone tracks and temporary URLs are released.
- Only the recording is sent to OpenAI, via the same-origin server route. Journal text and photos are not sent. Waffle doesn't persist the audio; service-side processing is subject to OpenAI's data policies. Transcription errors keep the recording in memory for retry.

## Vercel setup

Use the Next.js framework preset, build command `npm run build`, and the default output directory. Remove any custom `out` output-directory override from the earlier static deployment. This version needs a server function at `/api/transcribe`.

Add these **server-only** environment variables to the relevant Vercel deployment environments, then redeploy:

- `OPENAI_API_KEY`: a key from your OpenAI API project with transcription access and billing configured.
- `WAFFLE_DICTATION_TOKEN`: a random private access code of at least 24 characters. Generate it locally, for example with `openssl rand -hex 24`. Enter that code in Waffle's dictation dialog. Never enter your OpenAI API key in the app.

Neither variable should start with `NEXT_PUBLIC_`, be committed, or be pasted into chat. Local setup uses `.env.local`; `.env.example` documents the names without values. Restart the dev server after changing local variables.

The access code is a private-pilot gate, not a multiuser account system. It is held only in component memory. There is no durable rate limiter or per-user quota yet; before broader release add authenticated accounts and enforce usage limits. Use a dedicated API project to monitor paid usage. Missing configuration disables transcription with an explanatory error; ordinary journalling and backups continue to work.

## Hosting and Android boundary

Next.js now builds a server deployment instead of `out/`. The editor and IndexedDB still run entirely in the browser. The offline build script generates `public/sw.js` from `.next/static` and public assets. It never caches `/api/` or recordings. A future Capacitor package must build the client separately and configure its hosted transcription endpoint; do not point Capacitor at the old stale `out/` folder.

## Verification

Automated tests cover backup byte-for-byte round trip, malformed files, duplicate/impossible dates, safe merge, explicit replacement, transaction rollback, storage reopening, and transcription authorization, limits, request shape, provider error handling. Provider calls use a test double and do not send real audio or spend API credit.

Phone acceptance: export a real backup and retain it, import on another browser, compare text/photos, verify keep-existing behaviour, record a short phrase, stop/listen, transcribe, edit and append, then reopen. Test microphone denial, network interruption and offline journalling. Live transcription requires configured credentials and a real microphone test.
